MỤC LỤC:
  PHẦN 1: CHUẨN BỊ MÔI TRƯỜNG VÀ MẠNG LAN
  PHẦN 2: THỰC HÀNH PHÂN TÁN TRÊN 2 MÁY THẬT (CHUẨN BTL)

================================================================================
PHẦN 1: CHUẨN BỊ MÔI TRƯỜNG VÀ MẠNG LAN
================================================================================
1. Cài đặt MongoDB:
   - Tất cả các máy tham gia đều phải cài đặt MongoDB Community Server và MongoDB Shell (mongosh).
   - Đảm bảo biến môi trường PATH đã nhận lệnh `mongod` và `mongosh`.

2. Kết nối chung một mạng:
   - Cả 2 máy phải bắt chung 1 mạng Wi-Fi (hoặc cắm chung dây switch mạng LAN, hoặc phát Wi-Fi từ điện thoại cho cả 2 máy kết nối).

3. Lấy địa chỉ IP của từng máy:
   - Trên mỗi máy, mở PowerShell/CMD và gõ:
       ipconfig
   - Tìm dòng "IPv4 Address", ví dụ:
       Máy A: 192.168.1.15  (Ghi nhớ là IP_MAY_A)
       Máy B: 192.168.1.25  (Ghi nhớ là IP_MAY_B)

4. Kiểm tra thông mạng (Ping):
   - Từ Máy A gõ: ping 192.168.1.25
   - Từ Máy B gõ: ping 192.168.1.15
   - Nếu thấy phản hồi "Reply from ... bytes=32 time=..." là thông mạng thành công.

5. Tắt tường lửa (QUAN TRỌNG NHẤT):
   - Tường lửa Windows thường chặn các cổng mạng lạ.
   - Để tránh lỗi, hãy TẮT Windows Defender Firewall trên cả 2 máy trong lúc thực hành (hoặc mở inbound rules cho các cổng: 27017, 27018, 27019, 27020).


================================================================================
PHẦN 2: THỰC HÀNH PHÂN TÁN TRÊN 2 MÁY THẬT (MÔ HÌNH CHUẨN)
================================================================================
Mô hình phân công vai trò:
- MÁY A (Máy Master & Cơ sở Hà Nội):
    + Config Server: Lưu metadata cụm phân tán (Cổng 27019)
    + Shard 1: Chứa dữ liệu Bệnh viện Hà Nội (Cổng 27018)
    + mongos: Router tiếp nhận truy vấn chính (Cổng 27017)
- MÁY B (Máy Worker & Cơ sở TP.HCM):
    + Shard 2: Chứa dữ liệu Bệnh viện TP.HCM (Cổng 27018)
    (Máy B không cần code hay script gì cả!)

--------------------------------------------------------------------------------
BƯỚC 1: TẠO THƯ MỤC LƯU DỮ LIỆU TRÊN 2 MÁY
--------------------------------------------------------------------------------
- Trên Máy A, mở PowerShell gõ:
    mkdir C:\mongo_cluster\configdb
    mkdir C:\mongo_cluster\shard1

- Trên Máy B, mở PowerShell gõ:
    mkdir C:\mongo_cluster\shard2

--------------------------------------------------------------------------------
BƯỚC 2: KHỞI ĐỘNG CÁC TIẾN TRÌNH DATABASE
--------------------------------------------------------------------------------
* TRÊN MÁY A: Mở 2 cửa sổ PowerShell riêng biệt:
  - Cửa sổ A1 (Bật Config Server):
      mongod --configsvr --replSet configReplSet --port 27019 --dbpath "C:\mongo_cluster\configdb" --bind_ip_all

  - Cửa sổ A2 (Bật Shard 1 - Hà Nội):
      mongod --shardsvr --replSet shard1ReplSet --port 27018 --dbpath "C:\mongo_cluster\shard1" --bind_ip_all

  (Giữ nguyên 2 cửa sổ này chạy ngầm, không đóng lại!)

* TRÊN MÁY B: Mở 1 cửa sổ PowerShell:
  - Cửa sổ B1 (Bật Shard 2 - TP.HCM):
      mongod --shardsvr --replSet shard2ReplSet --port 27018 --dbpath "C:\mongo_cluster\shard2" --bind_ip_all

  (Giữ nguyên cửa sổ này chạy ngầm, không đóng lại!)

--------------------------------------------------------------------------------
BƯỚC 3: KHỞI TẠO CÁC REPLICA SET (CHỈ THAO TÁC TẠI MÁY A)
--------------------------------------------------------------------------------
Mở thêm 1 cửa sổ PowerShell mới trên MÁY A và chạy lần lượt 3 lệnh sau (Nhớ thay đúng IP thật của máy bạn):

1. Khởi tạo Config Server:
   mongosh --port 27019 --eval "rs.initiate({ _id: 'configReplSet', configsvr: true, members: [{ _id: 0, host: '<IP_MAY_A>:27019' }] })"

2. Khởi tạo Shard 1 (Máy A):
   mongosh --port 27018 --eval "rs.initiate({ _id: 'shard1ReplSet', members: [{ _id: 0, host: '<IP_MAY_A>:27018' }] })"

3. Khởi tạo Shard 2 (Gửi lệnh kích hoạt sang Máy B qua mạng):
   mongosh --host <IP_MAY_B> --port 27018 --eval "rs.initiate({ _id: 'shard2ReplSet', members: [{ _id: 0, host: '<IP_MAY_B>:27018' }] })"

--------------------------------------------------------------------------------
BƯỚC 4: BẬT ROUTER MONGOS (TRÊN MÁY A)
--------------------------------------------------------------------------------
Mở thêm 1 cửa sổ PowerShell trên MÁY A và gõ lệnh chạy Router:
   mongos --configdb configReplSet/<IP_MAY_A>:27019 --port 27017 --bind_ip_all

(Cửa sổ này sẽ chạy Router tiếp nhận mọi kết nối ở cổng 27017).

--------------------------------------------------------------------------------
BƯỚC 5: NẠP SHARD VÀ CẤU HÌNH ZONE SHARDING ĐỊA LÝ
--------------------------------------------------------------------------------
Mở 1 PowerShell mới trên MÁY A, kết nối vào mongos:
   mongosh --port 27017

Sau khi vào màn hình mongosh, dán nguyên đoạn code sau vào:

// 1. Thêm 2 shard vật lý vào cụm
sh.addShard("shard1ReplSet/<IP_MAY_A>:27018");
sh.addShard("shard2ReplSet/<IP_MAY_B>:27018");

// 2. Kích hoạt sharding cho DB bệnh viện
sh.enableSharding("hospital_ehr_db");

// 3. Gán thẻ địa lý: shard1 là Hà Nội, shard2 là TP.HCM
sh.addShardTag("shard1ReplSet", "ZONE_HN");
sh.addShardTag("shard2ReplSet", "ZONE_HCM");

// 4. Chọn Shard Key cho bệnh án: { hospital_branch: 1, patient_id: 1 }
sh.shardCollection("hospital_ehr_db.encounters", { hospital_branch: 1, patient_id: 1 });

// 5. Cấu hình Range: Chi nhánh HN tự đổ về Máy A, HCM tự đổ về Máy B
sh.addTagRange(
  "hospital_ehr_db.encounters",
  { hospital_branch: "HN", patient_id: MinKey },
  { hospital_branch: "HN", patient_id: MaxKey },
  "ZONE_HN"
);
sh.addTagRange(
  "hospital_ehr_db.encounters",
  { hospital_branch: "HCM", patient_id: MinKey },
  { hospital_branch: "HCM", patient_id: MaxKey },
  "ZONE_HCM"
);

print("=== ĐÃ CẤU HÌNH XONG ZONE SHARDING TRÊN 2 MÁY! ===");

--------------------------------------------------------------------------------
BƯỚC 6: CHẠY SCRIPT TẠO SCHEMA VÀ NẠP DỮ LIỆU
--------------------------------------------------------------------------------
Trên MÁY A, vào thư mục `D:\BTL\BTL_CSDLPT\scripts` và chạy:
   mongosh --port 27017 hospital_ehr_db < 01_init_schema_and_indexes.js
   mongosh --port 27017 hospital_ehr_db < 02_seed_data.js


================================================================================
PHẦN 3: HƯỚNG DẪN MỞ RỘNG LÊN 3 MÁY HOẶC NHIỀU MÁY HƠN
================================================================================
Nếu nhóm của bạn có 3 hoặc 4 máy tính muốn cùng tham gia vào bài tập lớn:

Kịch bản 3 Máy (Hà Nội - Đà Nẵng - TP.HCM):
- MÁY A: IP_A -> Đóng vai trò Config Server (27019) + mongos Router (27017)
- MÁY B: IP_B -> Đóng vai trò Shard 1 (Cơ sở Hà Nội - ZONE_HN, port 27018)
- MÁY C: IP_C -> Đóng vai trò Shard 2 (Cơ sở TP.HCM - ZONE_HCM, port 27018)
- MÁY D (Nếu có): IP_D -> Đóng vai trò Shard 3 (Cơ sở Đà Nẵng - ZONE_DN, port 27018)

Cách thực hiện:
1. Trên mỗi Máy B, C, D: Bật 1 tiến trình `mongod` với tên Replica Set riêng:
   - Máy B: mongod --shardsvr --replSet shard1ReplSet --port 27018 --dbpath "C:\mongo_cluster\shard1" --bind_ip_all
   - Máy C: mongod --shardsvr --replSet shard2ReplSet --port 27018 --dbpath "C:\mongo_cluster\shard2" --bind_ip_all
   - Máy D: mongod --shardsvr --replSet shard3ReplSet --port 27018 --dbpath "C:\mongo_cluster\shard3" --bind_ip_all

2. Trên Máy A (Router):
   Chỉ cần thêm shard thứ 3 vào:
   sh.addShard("shard3ReplSet/<IP_MAY_D>:27018");
   sh.addShardTag("shard3ReplSet", "ZONE_DN");
   sh.addTagRange(
     "hospital_ehr_db.encounters",
     { hospital_branch: "DN", patient_id: MinKey },
     { hospital_branch: "DN", patient_id: MaxKey },
     "ZONE_DN"
   );


================================================================================
PHẦN 4: KIỂM CHỨNG DỮ LIỆU ĐÃ PHÂN TÁN (ĐỂ CHẤM ĐIỂM BTL)
================================================================================
Khi trình bày trước giảng viên, bạn thực hiện 3 thao tác chứng minh sau:

THAO TÁC 1: Xem báo cáo phân bổ phân mảnh (Chạy từ MÁY A trên mongos)
- Lệnh:
    mongosh --port 27017 hospital_ehr_db --eval "db.encounters.getShardDistribution()"
- Kết quả mong đợi:
    + Shard shard1ReplSet (Máy A): Chứa 2 documents (các ca khám ở Hà Nội).
    + Shard shard2ReplSet (Máy B): Chứa 1 document (ca khám ở TP.HCM).

THAO TÁC 2: Soi trực tiếp vào ổ cứng MÁY B (Không qua Router)
- Sang Máy B, mở PowerShell gõ:
    mongosh --port 27018 hospital_ehr_db --eval "db.encounters.find({}, { encounter_code: 1, hospital_branch: 1 })"
- Kết quả: Máy B CHỈ nhìn thấy ca bệnh của chi nhánh "HCM", hoàn toàn KHÔNG có ca của "HN".
-> Chứng minh dữ liệu chi nhánh nào đã được lưu tách biệt trên máy tính vùng đó!

THAO TÁC 3: Chứng minh tính trong suốt (Transparency)
- Đứng ở Máy A gõ qua mongos (cổng 27017):
    mongosh --port 27017 hospital_ehr_db --eval "db.encounters.countDocuments()"
- Kết quả: Trả về đầy đủ 3 ca bệnh!
-> Dù dữ liệu bị xé đôi lưu ở 2 máy tính vật lý khác nhau, hệ thống vẫn hiển thị đồng nhất.


================================================================================
PHẦN 5: CÁC LỖI THƯỜNG GẶP VÀ CÁCH KHẮC PHỤC
================================================================================
1. Lỗi "Connection refused" / "timed out when connecting to <IP>:27018":
   - Nguyên nhân: Tường lửa Windows trên máy đích đang chặn kết nối.
   - Khắc phục: Vào "Windows Defender Firewall" -> Chọn "Turn Windows Defender Firewall on or off" -> Tắt tạm thời cả Private và Public Network.

2. Lỗi "Host unreachable":
   - Nguyên nhân: 2 máy chưa thông mạng Wi-Fi (hoặc Wi-Fi trường/công ty bật tính năng AP Isolation cấm 2 thiết bị nội bộ nói chuyện với nhau).
   - Khắc phục: Dùng 1 điện thoại phát Wi-Fi Personal Hotspot cho cả 2 máy kết nối vào, hoặc cắm 1 sợi dây mạng LAN nối trực tiếp giữa 2 máy.

3. Lỗi "mongod --dbpath directory does not exist":
   - Khắc phục: Kiểm tra đã chạy lệnh `mkdir C:\mongo_cluster\...` tạo thư mục chưa.

4. Muốn làm sạch làm lại từ đầu:
   - Tắt tất cả các cửa sổ PowerShell.
   - Xóa sạch toàn bộ thư mục `C:\mongo_cluster`.
   - Tạo lại thư mục và thực hiện lại từ Bước 1.
